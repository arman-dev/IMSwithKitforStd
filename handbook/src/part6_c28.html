২. নিজেই বলে "প্রোডাকশনে চালাবেন না"

runserver চালু হলেই সতর্কবার্তা দেয়; নিরাপত্তা হার্ডেনিং, স্ট্যাটিক ফাইল, লগ — কোনোটাই এর কাজ নয়।

৩. DEBUG=True মানে সব গোপন তথ্য পর্দায়

একটি এরর হলেই সেটিংস, SQL, ফাইল-পথ — যা কিছু দরকার। শিক্ষকের ব্রাউজারে সেটি দেখানো মানে সেটি ফাঁস করা।

তাই ডিপ্লয়মেন্ট মানে কেবল "অন্য কম্পিউটারে চালানো" নয় — অন্য একটি ভঙ্গি: কঠোর সেটিংস, সত্যিকারের অ্যাপ সার্ভার, আসল ডেটাবেস, আর পেছনে ওয়েব সার্ভার।
শিক্ষকের নোট: প্রথম প্রশ্ন করুন: "আপনার প্রজেক্ট সার্ভারে দিলে কী হবে?" বেশিরভাগ উত্তর "চলবে" — আসল উত্তর "চলবে, কিন্তু ভাঙবে"।

# config/settings/base.py
def env(key, default=None):
    value = os.environ.get(key, default)
    if value is None:
        raise RuntimeError(
            f"Missing required environment "
            f"variable: {key}. Copy .env.example "
            f"to .env and fill it in.")
    return value

def env_bool(key, default=False):
    return env(key, str(default)).strip().lower() \
        in {"1", "true", "yes", "on"}

def env_list(key, default=""):
    raw = env(key, default)
    return [x.strip() for x in raw.split(",") if x.strip()]

CSRF টোকেন

ফর্মের গোপন মান — কী জানলে ক্রস-সাইট অনুরোধে অনুকরণ সহজ।

বানানো: python -c "import secrets; print(secrets.token_urlsafe(50))" — ৫০+ অক্ষর, প্রতিটি পরিবেশে আলাদা।
ফাঁস হলে: কী পাল্টান → সব সেশন বাতিল হবে (সবাই আবার লগইন করবে), রিসেট লিংকের পুরোনো টোকেনও অচল।
শিক্ষকের নোট: জোর দিন: এই কী রোটেট করলে ব্যবহারকারীদের লগআউট হয়ে যায় — সেটি দোষ নয়, নিরাপত্তার দাম। রাতে করুন, ব্যবহার কম থাকলে।
ঠিকানা

ALLOWED_HOSTS ও CSRF_TRUSTED_ORIGINS

দুটি আলাদা দরজা, দুটি আলাদা আক্রমণ
সেটিংকোন আক্রমণ থামায়ভুল হলে লক্ষণ
ALLOWED_HOSTSHost হেডারের জালিয়াতি — অন্য ডোমেইনের নামে অনুরোধ পাঠিয়ে পাসওয়ার্ড-রিসেট লিংক বিষাক্ত করাঅচেনা হোস্টে 400 Bad Request
CSRF_TRUSTED_ORIGINSঅন্য সাইট থেকে ফর্ম সাবমিট — লগইন থাকা ব্রাউজার দিয়েhttps ডোমেইনে সাবমিট করলে 403 CSRF
SECURE_PROXY_SSL_HEADERপ্রক্সির পেছনে থাকা অ্যাপকে "এটি https" বোঝানোঅসীম রিডাইরেক্ট লুপ
IMS-এ: ALLOWED_HOSTS="*" হলে prod.py চালুই হয় না — এই ফাঁদটা কাঠামোগতভাবে বন্ধ।
বাস্তব ফল: সাবডোমেইন বা কাস্টম ডোমেইন যোগ করলে এই দুটি তালিকা দুই জায়গায় আপডেট করতে হয় — নইলে 400/403।
শিক্ষকের নোট: প্রশ্ন: "আইপি দিয়ে টেস্ট করছি, ডোমেইন নেই — তখন কী?" উত্তর: হোস্টের দেওয়া ডোমেইনটাই লিখুন; * দিয়ে "পরে ঠিক করব" সবচেয়ে সাধারণ ও সবচেয়ে বিপজ্জনক অভ্যাস।

সাতটি সুইচ একসাথে

prod.py-তে যা ইতিমধ্যেই চালু
সেটিংমানকার কাজ
SECURE_SSL_REDIRECTTruehttp → https
SECURE_HSTS_SECONDS2592000 (৩০ দিন)ব্রাউজারকে বলে: এই সাইটে আর কখনো http নয়
SECURE_HSTS_PRELOADTrueব্রাউজার-তালিকায় স্থায়ী এন্ট্রি
SESSION_COOKIE_SECURETrueসেশন কুকি কেবল https-এ যাবে
CSRF_COOKIE_SECURETrueএকই নিয়ম CSRF কুকিতে
SESSION_COOKIE_HTTPONLYTrueজাভাস্ক্রিপ্ট কুকি পড়তে পারবে না
X_FRAME_OPTIONSDENYঅন্য সাইটে iframe-এ বসানো যাবে না
HSTS-এর ফাঁদ: একবার ব্রাউজার এই হেডার পেলে ৩০ দিন https-ই দাবি করবে। সার্টিফিকেট না থাকলে সাইট খুলবেই না — তাই TLS আগে, HSTS পরে।
শিক্ষকের নোট: প্রথম দিনেই preload জমা দেবেন না — ৩০ দিন চালু রেখে সমস্যা নেই দেখে তারপর। ভুল হলে ফেরানো কঠিন, কারণ ব্রাউজারে হেডার জমে থাকে।
