রিলিজ

একটি রিলিজের তিনটি ধাপ

build → release → web; তিনটির দায়িত্ব আলাদা
# build.sh
pip install -r requirements-prod.txt
python manage.py collectstatic --noinput
python manage.py migrate --noinput

# Procfile
release: python manage.py migrate --noinput
web: gunicorn config.wsgi:application \
     --bind 0.0.0.0:$PORT --workers 3 \
     --timeout 60 --access-logfile - \
     --error-logfile -
ধাপকেন আলাদা
buildনির্ভরতা + স্ট্যাটিক — একবার, ইমেজ তৈরি হওয়ার সময়
releaseস্কিমা বদল — নতুন কোড চালু হওয়ার ঠিক আগে, একবার
webঅনুরোধ সামলানো — একাধিক worker, যেকোনো সময় বন্ধ হতে পারে
ঝুঁকি: ৩ worker একসাথে চালু হলে migrate একবারই হয় (release ধাপে) — কিন্তু worker মাঝপথে নতুন স্কিমা পেলে পুরনো কোড ভাঙতে পারে। ব্লু-গ্রিন ডিপ্লয় নেই।
--timeout 60: ৬০ সেকেন্ডে উত্তর না দিলে worker মারা যায় — PDF/রিপোর্ট বড় হলে এই সীমা ছুঁতে পারে।
শিক্ষকের নোট: "worker মাঝপথে নতুন স্কিমা" — এটি বোঝানো কঠিন কিন্তু জরুরি। উদাহরণ: কলামের নাম বদলালে পুরনো worker ভাঙবে; তাই দুই ধাপে নাম বদলানো হয় (যোগ → ব্যবহার → পুরনো মোছা)।
