যা ইচ্ছাকৃতভাবে রাখা হয়নি

প্রতিটি বাদ দেওয়া একটা সিদ্ধান্ত — আর একটা সীমা
যা নেইকেন বাদকখন দরকার হবে
React / SPA২ ভূমিকা, ৮৫ রুট, ফর্ম-ভারী পর্দা — server-rendered HTML যথেষ্ট; একটি বিল্ড-ধাপ কম মানে একটি ভাঙার জায়গা কমযখন অফলাইন বা রিয়েল-টাইম হাজিরা দরকার হবে
Celery / Redisএখন কোনো কাজই ব্যাকগ্রাউন্ডে চলে না; PDF ১ সেকেন্ডে হয়ইমেইল-বাল্ক, রিপোর্ট-জেনারেশন, রিমাইন্ডার
Dockerডেমোটি bash run.sh — শিক্ষার্থীর মেশিনে Docker মানে আরও একটি ইনস্টলদল বড় হলে, বা সার্ভার একাধিক হলে
GraphQL / REST APIএখন কনজিউমার কেবল ব্রাউজার; API বানালে সেটি রক্ষণাবেক্ষণের আরও একটি চুক্তিমোবাইল অ্যাপ এলে (D2-এর বাইরে, ভবিষ্যৎ ডেকে)
মাইক্রোসার্ভিসএকই ডেটাবেজ, একই ট্রানজেকশন — ভাগ করলে JOIN-ই HTTP কল হয়ে যেতদল ২০+ হলে, আর ভিন্ন স্কেলিং দরকার হলে
ক্যাশ (Memcached)ডেটা ছোট, কোয়েরি indexed; ক্যাশ যোগ করলে "পুরনো ডেটা" বাগ আসেড্যাশবোর্ড ধীর হলে — মেপে দেখে
নিয়ম: প্রতিটি বাদ দেওয়া জিনিসের জন্য একটি লিখিত শর্ত — "কখন যোগ করব"। শর্ত ছাড়া বাদ দেওয়া মানে ভুলে যাওয়া।
শিক্ষকের নোট: শিক্ষার্থীরা প্রায়ই জিজ্ঞেস করে "React ছাড়া চলে?" — উত্তর: চলে, এবং এখানে সেটাই সঠিক সিদ্ধান্ত, কারণ সমস্যাটি UI-এর জটিলতা নয়, ডেটার নিয়মের জটিলতা। প্রতিটি সারিতে "কখন দরকার" কলামটি তুলে ধরুন।
