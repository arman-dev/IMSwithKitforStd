backup.sh — ৬টি কার্যকর লাইন

pg_dump -Fc · media tar · ১৪ দিন · set -euo pipefail
set -euo pipefail
STAMP=$(date +%Y%m%d-%H%M%S)
DEST="${BACKUP_DIR:-./backups}"
mkdir -p "$DEST"
pg_dump -Fc -f "$DEST/ims-$STAMP.dump"
tar -czf "$DEST/media-$STAMP.tar.gz" media/ || true
find "$DEST" -name '*.dump' -mtime +14 -delete
সিদ্ধান্তকারণ
ডেটাবেজ + media আলাদালোগো/ম্যাটেরিয়াল ডাম্পে থাকে না
-Fc ফরম্যাটটেবিল ধরে ধরে ফেরানো যায়
১৪ দিনদুই সপ্তাহের মধ্যে ভুল ধরা পড়ে
set -euo pipefailমাঝপথে ব্যর্থ = ব্যাকআপ নেই, আধা-ব্যাকআপ নয়
সীমা: ডিফল্ট গন্তব্য ./backups — অর্থাৎ সার্ভারের ভেতরেই। সার্ভার হারালে ব্যাকআপও যায়। অফসাইট কপি নেই, এনক্রিপশন নেই, WAL/PITR নেই।
আরও একটি: pg_dump চালানোর অনুমতি ও ডাটাবেজ-নাম কোথাও লেখা নেই — স্ক্রিপ্ট ধরে নেয় আপনি ওই মেশিনে PostgreSQL-এর সুপারইউজার। বাস্তবে এটি প্রথমেই আটকে যায়।
শিক্ষকের নোট: "ব্যাকআপ আছে" বাক্যটি কখনো প্রমাণ নয়। যা প্রমাণ: একটি ফাইল, একটি তারিখ, একটি আকার — আর একটি সফল রিস্টোর।
